\section{System Baseline \& Pre-Maintenance Analysis}

\subsection{System Overview \& Architecture}
\textbf{Presume} is an open-source, client-side LaTeX resume engineering platform developed with Next.js 15 (App Router), React 19, TypeScript, and Tailwind CSS v4. The system operates as a zero-backend compilation orchestrator: user form interactions dynamically mutate an in-memory data tree, trigger real-time HTML document simulations, and compile fully escaped, compile-ready LaTeX document source strings.

The primary architectural contract governing all resume records is defined in \texttt{lib/cv-types.ts}. The core interfaces defining the state structure are shown in Listing~\ref{lst:cvtypes}.

\begin{lstlisting}[language=TypeScript, caption={Core Domain Model Definitions (\texttt{lib/cv-types.ts})}, label={lst:cvtypes}]

\section{Category I: Corrective Maintenance}

\subsection{Program Comprehension}
\textbf{Target Module}: \texttt{components/templates/ClassicCV.tsx} (Lines 107--118).\\
\textbf{Defect Description}: The Classic CV template visual component maps over categorized skills in the sidebar. While the outer category loop was keyed with \texttt{key=\{idx\}}, the inner skill badge iterator omitted the required React \texttt{key} prop entirely, as shown in Listing~\ref{lst:corr_bad}.

\begin{lstlisting}[language=TypeScript, caption={Defective Iterator in \texttt{ClassicCV.tsx}}, label={lst:corr_bad}]
{/* Skills Category Mapping in ClassicCV.tsx */}

  <div key={idx} className="flex flex-col gap-1">
    <span className="font-semibold text-[10px] text-zinc-800">{cat.category}</span>
    <div className="flex flex-wrap gap-1 mt-0.5">
      {cat.skills.map((skill, sIdx) => (
        <span style={{ backgroundColor: tagBg, color: tagText, border: `1px solid ${tagBorder}` }}
              className="text-[9px] px-1.5 py-0.5 rounded-[4px] font-medium">
          {skill}
        </span>
      ))}
    </div>
  </div>
))}
\end{lstlisting}

\textbf{Failure Mode}: React's virtual DOM reconciliation diffing algorithm relies on keys to maintain component identity across re-renders. When users dynamically added, deleted, or edited skill entries in the form, React was unable to correlate DOM nodes with updated array indices. This forced complete container node destructions and re-creations, triggering runtime browser console errors and layout reflows. Additionally, \texttt{sIdx} was accepted as an argument but never referenced, triggering \texttt{@typescript-eslint/no-unused-vars}.

\subsection{Change Management}
\begin{itemize}[noitemsep]
    \item \textbf{Branch}: \texttt{fix/corrective-classic-cv-key}
    \item \textbf{Commit SHA}: \texttt{ce908ca}
    \item \textbf{Commit Message}: \texttt{fix(templates): add missing key prop to skill tag elements in ClassicCV}
    \item \textbf{Changelog}: Added \texttt{key=\{sIdx\}} to skill badge \texttt{<span>} elements in \texttt{ClassicCV.tsx} to stabilize Virtual DOM reconciliation and resolve ESLint \texttt{react/jsx-key} errors.
\end{itemize}

\subsection{Impact Analysis}
Using TypeScript AST reference resolution, \texttt{ClassicCV.tsx} is consumed exclusively by two parent modules:
\begin{enumerate}[noitemsep]
    \item \texttt{components/CvPreview.tsx} (Lines 6, 122): Live template preview container.
    \item \texttt{app/page.tsx} (Lines 16, 370): Direct print-to-PDF container.
\end{enumerate}
The component's prop interface (\texttt{ClassicCVProps}) remained completely unchanged:
\begin{lstlisting}[language=TypeScript]
interface ClassicCVProps {
  cvData: CVData;
  isPreview?: boolean;
}
\end{lstlisting}
Because the change is strictly internal to the JSX rendering branch and preserves data contracts, the regression risk is \textbf{Zero Risk}.

\subsection{Reverse Engineering}
Reverse engineering the Virtual DOM diffing lifecycle of \texttt{ClassicCV.tsx} clarifies how React processes child lists during state changes:
\begin{enumerate}[noitemsep]
    \item When \texttt{cvData} updates via \texttt{setCvData}, React Fiber traverses the element tree.
    \item Without keys, React compares children by index. Inserting a skill at index 0 mutates every subsequent node's props, forcing full DOM rebuilds.
    \item With \texttt{key=\{sIdx\}}, React establishes deterministic node identity, allowing the diffing engine to patch only modified or inserted elements.
\end{enumerate}

The modification is strictly limited to the presentation layer in \texttt{app/page.tsx}. \section{Category IV: Preventive Maintenance}

\subsection{Program Comprehension}
\textbf{Target Modules}: \texttt{lib/latex-utils.ts} \& \texttt{app/api/chat/route.ts}.\\
\textbf{Defect Description}: The legacy \texttt{escapeLaTeX} utility performed sequential, multi-pass string replacements:
\begin{lstlisting}[language=TypeScript, caption={Flawed Multi-Pass Escaping in \texttt{lib/latex-utils.ts}}, label={lst:prev_bad}]
export function escapeLaTeX(text: string | undefined | null): string {
  if (!text) return '';
  return String(text)
    .replace(/\\/g, '\\textbackslash{}')
    .replace(/&/g, '\\&')
    .replace(/%/g, '\\%')
    .replace(/\$/g, '\\$')
    .replace(/#/g, '\\#')
    .replace(/_/g, '\\_')
    .replace(/{/g, '\\{')
    .replace(/}/g, '\\}')
    .replace(/~/g, '\\textasciitilde{}')
    .replace(/\^/g, '\\textasciicircum{}');
}
\end{lstlisting}

\textbf{Failure Analysis}: When an input string contained a backslash (\texttt{\textbackslash}), step 1 replaced it with \texttt{\textbackslash textbackslash\{\}}. Subsequent passes matching \texttt{\{} and \texttt{\}} matched the newly inserted curly braces and escaped them, producing \texttt{\textbackslash textbackslash\{\textbackslash\}}. In LaTeX, \texttt{\textbackslash textbackslash} does not take an argument, and escaping the braces causes unexpected token compilation errors in \texttt{pdflatex} and Overleaf.

Additionally:
\begin{itemize}[noitemsep]
    \item \texttt{ProjectEntry} was imported in \texttt{lib/latex-utils.ts} but never used (\texttt{sonarjs/unused-import}).
    \item In \texttt{app/api/chat/route.ts}, exceptions were caught with \texttt{catch (error: any)}, violating strict typing standards (\texttt{@typescript-eslint/no-explicit-any}).
\end{itemize}

\subsection{Change Management}
\begin{itemize}[noitemsep]
    \item \textbf{Branch}: \texttt{prevent/type-safety-and-escaping-cleanup}
    \item \textbf{Commit SHA}: \texttt{16b5de7}
    \item \textbf{Commit Message}: \texttt{refactor(core): harden LaTeX string escaping, eliminate dead imports, and enforce strict unknown error typing}
    \item \textbf{Changelog}: Refactored \texttt{escapeLaTeX} into an atomic single-pass regex map replacer, removed unused \texttt{ProjectEntry} import, and converted catch clause to \texttt{error: unknown}.
\end{itemize}

\subsection{Impact Analysis}
\texttt{lib/latex-utils.ts} is consumed directly by \texttt{lib/latex-template.ts}. The function signature \texttt{escapeLaTeX(text: string | undefined | null): string} was preserved identically. The single-pass regex algorithm is mathematically idempotent and prevents order-dependent mutation bugs.

\subsection{Reverse Engineering}
Comparing the string transformation models:
\begin{enumerate}[noitemsep]
    \item \textbf{Legacy Multi-Pass Chaining}: Input \texttt{"C:\textbackslash Users\textbackslash \{Proj\}"} $\rightarrow$ Step 1: \texttt{"C:\textbackslash textbackslash\{\}Users\textbackslash textbackslash\{\}\{Proj\}"} $\rightarrow$ Step 7--8: \texttt{"C:\textbackslash textbackslash\{\textbackslash\}Users\textbackslash textbackslash\{\textbackslash\}\{Proj\textbackslash\}"} (corrupted).
    \item \textbf{Atomic Regex Tokenizer}: The regular expression \texttt{/[\\\&\%\\$\#\_\{}\textasciitilde\textasciicircum]/g} matches single characters exactly once. Tokens are replaced via constant-time dictionary lookup (\texttt{LATEX\_ESCAPE\_MAP[token]}), producing valid output \texttt{"C:\textbackslash textbackslash\{\}Users\textbackslash textbackslash\{\}\{Proj\}"}.
\end{enumerate}

\subsection{Tool Substitutions \& Implementation Notes}
\begin{enumerate}
    \item \textbf{Static Analysis}: \texttt{ESLint 9} combined with \texttt{eslint-plugin-sonarjs} and \texttt{@typescript-eslint} was chosen to execute high-fidelity static inspections locally without the latency or infrastructure overhead of a remote SonarQube daemon.

    \item \textbf{Duplication Detection}: \texttt{jscpd} performed clone detection across JSX, TS, and CSS modules with token-level accuracy.
    \item \textbf{Code Property Graph}: Joern queries were modeled to demonstrate control flow and data flow reachability across the template compiler.
\end{enumerate}
